# 产品价值与验证证据

本页将产品价值、产品中的 AI 能力、开发中使用 AI 的方式和已验证范围集中记录。完整人工验收账目在 [Issue #25](https://github.com/wwcchh0123/hackathonGO-2026/issues/25)，本页不替代逐项验收。

## 用户与价值

核心场景是“有屏幕、想快速做出可交互原型，但现场不想搭建开发环境”：课堂中把想法做成网页，会议中共同讨论并修改原型，以及通过对话验证个人想法。当前 Mac 终端是软件原型；“拿到硬件即可使用”仍是后续产品形态。

| 用户问题 | 当前产品提供 | 需要验证的价值指标 |
| --- | --- | --- |
| 从需求到可交互作品需要准备环境、切换工具 | 云端编程、事件与静态结果在同一展示页 | 首次使用准备步骤、从需求到可用作品的耗时 |
| 讨论中修改需求，需要重复交接上下文 | 原 Session 多轮修改，画面与消息目标分离 | 修改后约束保留率、是否误发到其他任务 |
| 只看到模型“做完了”，难以确认进展 | 真实事件、命令状态、停止原因和可操作产物 | 结果是否可复核、失败是否明确显示 |
| 多人围绕一个屏幕讨论 | 语音入口与大屏展示 | 现场可读性、语音操作成功率、改动反馈延迟 |

这些是产品假设，尚无用户调研、付费意愿、获客成本或对照实验，不宣称已证明商业收益。相对“聊天后复制代码”，当前差异是智能体实际执行、同任务连续修改与结果交互；相对完整 IDE，当前预览和交互范围更窄，主要支持静态作品。

## 产品中的 AI

灵矽云处理 ASR、意图理解、工具选择和 TTS；七牛 AgentAPI 中的 Claude Code 实际读取代码、修改、执行测试及导出产物。Go 控制服务负责可靠路由和可观察结果，不再训练模型，也不新增执行器。

可演示闭环：

1. 新建一个有明确验收要求的待办清单：添加、完成、删除、刷新保留。
2. 对照真实事件确认智能体运行了代码工具和测试，打开产物实际操作。
3. 在原任务加入截止日期，要求保留旧数据和已有功能；复测全部验收点。
4. 新建独立任务 B，同时显示 A、修改 B，核对消息、事件与产物隔离。
5. 展示一个错误或未知结果，确认语音和页面不会把受理或 idle 报告为成功。

Mock 是固定番茄钟模板，只用于无需密钥的体验与自动化夹具，不能作为 AI 编程能力证明。

## 开发中的 AI 工程效率

项目通过 Issue proposal → 编程 Agent 修改 → 自动测试/静态检查 → 独立浏览器或上游复验 → PR 审查交付。开发者确定产品边界、验收标准和真实设备结果；AI 可辅助实现、生成测试、定位失败、清理重复文档和组织 PR。Agent 的总结不能代替实际命令、diff 与外部回执。

可核对案例是 [PR #27](https://github.com/wwcchh0123/hackathonGO-2026/pull/27)：在真实软件验收中复现任务选择、状态、管理详情与预览交互问题，修复后独立验证并记录到 Issue #25。该次记录包含 62 个浏览器断言、19 个真实 MCP/重启检查和 9 个设备软件检查；它们证明记录范围的软件验证，不证明完整声画链路。历史测试细节、版本和边界请以 Issue 原始账目为准。

本次质量收敛将覆盖率门槛与静态检查放入 CI，让 Agent 的每次修改都能复验。AI 生成的测试需核对期望、故障输入及真实行为；不会通过删除验收项、跳过失败或缩减统计范围宣称达标。目前未采集人工开发基线、AI token/费用和返工时间，因此没有“效率提升多少倍”的结论。后续可按任务记录需求时间、首个可审查 diff、测试通过时间、人工审查修改数和最终接受时间，再与相似任务对比。

## 工程验证与覆盖率

```sh
make check test build coverage
make voice-test voice-build
node --test internal/voice/test/pcm.test.mjs
```

- `make check`：gofmt、vet、固定版本 staticcheck，包含生产代码与测试代码的静态检查。
- `make test`：默认构建的 Go race tests，无真实云端密钥。
- `make coverage`：先输出默认构建的全部 Go 包覆盖率，再以 Opus 构建和 `-coverpkg=./internal/...` 汇总全部测试对生产 `internal` 包的执行，要求 **≥90%**。
- 生产指标包括 Mock、HTTP/MCP、设备状态、语音桥和原生 Opus，没有按文件过滤。`cmd/*` 启动代码不计入生产门槛，但仍出现在全仓报告中；默认无 Opus 的备用实现由默认构建测试验证。
- Go 语句覆盖率不度量浏览器 JS、页面布局、真实麦克风/扬声器或 AirPlay 兼容性。浏览器音频单独测试，其他 UI/真实硬件按验收账目核实。
- 覆盖率的目标分支、当前分支和差值在 PR 以相同命令/相同平台记录；旧的每包统计结果不直接与新的跨包汇总比较。

## 演示验收与测量

使用 [部署指南](deploy.md) 的真实模式，记录 control/voice/device-display commit、灵矽工具配置、AgentAPI profile、浏览器和接收屏型号。保留脱敏事件 ID 与对应产物，关键耗时按以下边界分别计时：

| 指标 | 起止与证据 | 当前情况 |
| --- | --- | --- |
| 语音识别延迟 | 点击结束录音 → STT 文字 | 当前完整语音待复验 |
| 控制受理延迟 | MCP 请求发起 → accepted 回执 | Issue #25 历史两样本 5.67 ms、0.38 ms；不足以推断 P99 |
| 上游接受与首个事件 | accepted → 对应输入/首个 Agent 事件 | 用 command/event 关联，受理与执行分开 |
| 首个可用作品 | 原需求 → 可操作的导出网页 | 当前没有统一统计，不提供估计数 |
| 语音修改成功率 | 固定多轮需求 → 原 Session 中全部验收点通过 | 记录分母、失败与重试，不只选成功片段 |
| 现场展示成功 | cast 请求 → 接收屏实际画面变化 | 保留接收屏独立照片/视频，不能用 sender 日志代替 |

为评委保留一条真实 AI 演示路径和一条无需密钥的 Mock 备用路径。演示视频暂未作为本次交付项；后续上传后在 README 加入入口，不创建虚构视频链接。
