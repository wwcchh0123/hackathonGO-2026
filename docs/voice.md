# Mac 语音客户端启动指南

本文用于启动当前已经实现的灵矽语音客户端：使用 Mac 的麦克风和扬声器，与控制台绑定的灵矽智能体对话。客户端入口为 `cmd/voice`，默认页面地址为 `http://127.0.0.1:8090`。

## 日常启动

完成首次安装并绑定设备后，在仓库目录运行：

```sh
cd /path/to/hackathonGO-2026
make voice
```

保持这个终端运行，用浏览器打开 [语音客户端](http://127.0.0.1:8090)。依次点击「连接智能体」→「开始说话」，说完点击「说完了，发送」。

如果页面已经能打开，说明服务可能仍在运行，直接使用页面即可。如果启动提示 8090 端口被占用，先按后面的“常见问题”确认现有进程。

`make voice` 每次会先编译，再启动程序，所以更新 Go 代码或网页文件后仍可使用该命令。页面文件嵌入二进制，更新后需要重启程序并刷新网页。

## 在另一台 Mac 上首次安装

准备 macOS、Homebrew、Go 1.26+、命令行编译工具，以及支持麦克风和 AudioWorklet 的浏览器。建议使用 Chrome。安装和运行需要能访问 Go 模块源及灵矽服务。

进入自己的仓库目录；下面的示例路径请替换为实际克隆位置：

```sh
cd /path/to/hackathonGO-2026
```

检查命令行编译工具：

```sh
xcode-select -p
```

如果提示未安装，运行 `xcode-select --install`，在系统提示中完成安装后再继续。libopus 通过 Go 的 cgo 调用，因此构建语音程序需要 C 编译器。

在已安装 Homebrew 的前提下安装依赖，再下载项目的 Go 模块：

```sh
brew install go opus pkgconf
go version
pkg-config --modversion opus
make install
make voice
```

运行语音客户端无需 Node.js、前端构建、AgentAPI Key，也无需先启动 8080 的编程控制服务。

## 首次绑定和试说话

1. 打开 [本地语音页面](http://127.0.0.1:8090)。首次启动生成软件设备身份，页面和终端会显示六位激活码。
2. 登录 [灵矽智控台](https://xrobo.qiniu.com/)，进入要使用的智能体，在添加设备时填写该激活码并完成绑定。确保该智能体的模型和语音配置可用。
3. 等待页面显示“设备已绑定”。客户端约每 5 秒检查一次绑定状态；等待期间会定期刷新激活信息。
4. 点击「连接智能体」，等待页面显示“已连接 · 等你说话”。
5. 点击「开始说话」，在浏览器提示中允许麦克风；如果 macOS 也询问浏览器的麦克风权限，同样需要允许。
6. 说“你好，请介绍一下你自己”，然后点击「说完了，发送」。页面应显示识别文字、智能体回复文字，并播放语音。

录音期间音频已经实时上传，“说完了，发送”表示结束本轮输入。单次录音最长 60 秒，切换到后台会停止并发送。点击「停止播报」会停止当前回复；下一轮说话也会打断旧回复。

保留原设备身份文件后，后续启动无需重新绑定。如果云端结束了空闲会话，点击「重新连接」即可。

## 启动参数与配置位置

查看程序支持的参数：

```sh
make voice-build
./bin/voice -h
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `-listen` | `127.0.0.1:8090` | 本地 HTTP / WebSocket 地址，只支持本机回环地址 |
| `-data-dir` | `.data/voice` | 设备身份保存目录；相对路径以启动时的工作目录为准 |
| `-pair-only` | `false` | 仅激活/确认设备绑定，成功后退出，不启动网页和音频功能 |

使用自定义参数时，先构建，再直接运行二进制。例如，将本地端口改成 8091：

```sh
make voice-build
./bin/voice -listen 127.0.0.1:8091 -data-dir .data/voice
```

随后打开 `http://127.0.0.1:8091`。修改端口时保留原 `-data-dir`，可以继续使用同一台设备；建议先停止旧实例，再启动新实例。

如果从仓库外启动，使用绝对路径指定身份目录，避免意外生成另一台设备：

```sh
/path/to/hackathonGO-2026/bin/voice \
  -listen 127.0.0.1:8090 \
  -data-dir /path/to/hackathonGO-2026/.data/voice
```

配置分布如下：

| 内容 | 配置位置或获取方式 |
| --- | --- |
| 本地地址、身份目录 | 上述启动参数 |
| Device-Id、Client-Id | 自动生成并保存在身份目录下的 `identity.json` |
| 要连接的智能体、角色提示词、模型、音色 | 灵矽控制台中的设备绑定与智能体配置 |
| 设备 token、云端 WebSocket 地址 | 连接时从 OTA 自动获取，token 仅保留在 Go 内存中 |
| OTA 网关 | 当前使用代码默认值 `https://xrobo.qiniuapi.com/v1/ota/` |
| 手动录音模式、60 秒上限、输入音频参数 | 当前固定在代码中，未开放启动配置 |

当前语音客户端不读取 `.env`，也没有 YAML 配置文件。项目 `.env.example` 中的 AgentAPI、`CONTROL_TOKEN` 等用于 `cmd/control` 编程控制服务。

## 设备身份的保留

默认身份文件是仓库下的 `.data/voice/identity.json`。该文件包含生成的设备 ID 和客户端 UUID，已被 Git 忽略；重新编译和正常重启会继续使用它。

不要通过删除该文件解决连接问题。使用新的空身份目录会生成另一台软件设备，需要重新绑定。修改灵矽的角色、模型或音色后，先保存控制台配置，再在语音页面断开并重新连接即可。

如果只想先完成设备绑定，可以在仓库目录运行：

```sh
go run ./cmd/voice -pair-only
```

这条命令不需要原生 Opus 依赖。普通 `go run ./cmd/voice` 没有启用 Opus 构建标签，不能用于完整语音功能；完整启动使用 `make voice`。

## 检查、停止和重启

在另一个终端查询本地状态：

```sh
curl --max-time 5 http://127.0.0.1:8090/api/status
```

绑定完成且音频模块可用时，响应中的 `stage` 为 `paired`，`audio_available` 为 `true`。这表示设备准备就绪；真正语音连接成功以页面显示“已连接”为准。

在启动程序的终端按 `Ctrl+C` 停止服务。重启时再次运行：

```sh
cd /path/to/hackathonGO-2026
make voice
```

关闭网页会释放麦克风并断开对应语音会话，但 Go 服务仍在运行。只需再次打开页面连接即可。同一个服务实例一次只接受一个语音窗口。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| `address already in use` | 先打开本地页面确认是否已有客户端；运行下方 `lsof` 命令查看端口占用。若是自己此前启动的实例，在其终端按 Ctrl+C 后重启 |
| 找不到 `go`、`brew` 或 `pkg-config` | 确认对应工具已安装且位于 PATH；`pkg-config` 由 Homebrew 的 `pkgconf` 提供 |
| `Package opus was not found` | 运行 `brew install opus pkgconf`，再用 `pkg-config --modversion opus` 确认 |
| C 编译器或开发工具报错 | 完成 Xcode Command Line Tools 安装，再重新运行 `make voice-build` |
| 提示“音频编解码未启用” | 使用 `make voice`，不要用不带 Opus 构建标签的普通 `go run` 启动完整语音程序 |
| 一直显示等待绑定 | 确认使用页面当前激活码，并添加到目标智能体下；不要删除身份文件 |
| 无法启用麦克风 | 检查浏览器网站麦克风权限，以及 macOS“隐私与安全性”中的麦克风权限；确认输入设备正常 |
| 有识别文字却无回复 | 检查灵矽模型配置、额度和声纹限制，保存后重新连接 |
| 有回复文字但听不到声音 | 检查系统输出设备、音量和浏览器静音状态 |
| 提示另一个语音窗口已连接 | 在其他页面点击断开或关闭它，再重新连接 |
| 空闲一段时间后连接结束 | 点击重新连接；客户端会重新获取凭据，不会补发上一段录音 |
| 修改角色后没有变化 | 保存灵矽控制台配置，然后断开并重新连接 |

查看默认端口占用：

```sh
lsof -nP -iTCP:8090 -sTCP:LISTEN
```

## 连接编程与投屏

语音客户端只处理身份、音频和语音事件。它不会在本机启动 Claude Code，也不持有 AgentAPI Key；编程由独立控制服务连接 AgentAPI。按 [部署指南](deploy.md) 将控制 MCP 和设备 MCP 关联到灵矽智能体，工具角色配置以 [协议文档](protocol.md#灵矽配置与部署) 为准。

控制服务的 `DEVICE_ID` 可使用页面上的设备 ID。每次工具调用中的 `X-Linx-Device-Id` 用于设备路由；灵矽语音会话 ID、编程任务引用和 AgentAPI Session ID 含义不同。编程工具返回 `display_url` 后，智能体将完整地址交给设备 MCP 的 `cast_screen`。

点击“停止播报”只停止 TTS。编程暂停/继续通过 `send_message` 传给云端任务；停止投屏只改变画面输出。当前没有持续免按键自由对话；重连不保证恢复之前的灵矽对话上下文，也不会补发上次录音。

## 音频与身份边界

浏览器将麦克风音频连续重采样为 16 kHz 单声道 PCM，每帧 60 ms，经本地 WebSocket 交给 Go 编码为 Opus，再通过 WSS 发送到灵矽。回传音频按云端 hello 的采样率解码播放，不假定输入输出采样率相同。

设备 token 每次连接通过 OTA 获取，仅保留在 Go 内存中，不交给浏览器，不写入 URL 或日志。OTA 固件信息不会用于安装硬件固件。本地连接校验 Host/Origin，只允许本机回环地址和一个语音窗口。

开发测试和真实声画验收范围见 [Issue #25](https://github.com/wwcchh0123/hackathonGO-2026/issues/25)。

## 人物投屏版

统一容器的构建、端口和回滚步骤见 [人物模拟设备说明](../deploy/device-sim/README.md)。语音入口仍是 `http://127.0.0.1:8090/`；人物预览为 `http://127.0.0.1:8090/stage/`。点击连接和开始说话会唤醒已配置的投屏服务，原有设备绑定和云端 MCP 配置可以沿用。

未展示任务时，屏幕显示小狐狸；任务页展示时，人物缩到右下角。回答时气泡显示当前播放的句子，结束或打断后收起。点击「人物全屏 / 唤醒投屏」清除任务展示并回到人物画面；连接、开始说话和回复结束不会自动覆盖正在展示的任务页。
